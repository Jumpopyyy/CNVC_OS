# 尽调工作台与公共 Skill、Agent 库整合

## 范围与操作

保持“尽调清单、现场协同、数字分身”三个入口。公共方法继续由智能 Skill 库和智能 Agent 库维护；工作台只引用能力、保留使用版本及个人学习结果，不另建公共管理中心。“调用数字分身”仍只读取所有者确认发布的公开偏好和边界，最多五位。

生成清单可选择一个执行智能体和最多四项公共 Skill，可全部不选。支持提示词型 Agent 和现有文本工作流；带外部工具或插件执行权限的通用 Agent 不自动接入。本人的分身绑定能力按场景启用，可临时关闭；智能体已经加载的方法不重复注入。标准模式不解析或执行这些能力，始终不调用模型。工作流结果只作为分析建议，必须经原有结构化问题、材料逐字引用及专家依据校验，才能进入清单。保留人工编辑、排序、完成状态和原来的简洁 Word 导出。

数字分身中“管理辅助 Skill 与智能体”提供绑定、停用、场景设置和“提炼为个人 Skill 建议”。构建时也可临时选择方法或智能体。外部方法与本人已保存的偏好/案例整理为可编辑的待学习项；模型不可用时明确使用基础解析，员工确认前不修改偏好、不启用新 Skill。确认生成独立私有 Skill，保留来源版本、内容哈希和访问校验。原平台 Skill 导入也进入同一受控学习链路。

智能 Agent 库新增工作流“共享给公司 / 取消共享”，仅所有者可操作。发布前可以预览完整定义，并提示不得粘贴敏感项目原文。共享不授予模型或从属 Skill 权限，不共享项目附件或平台模型凭据；未经共享的个人工作流不能被其他员工读取或调用。

## 接口与数据

- `GET /api/due-diligence/library?projectId=...`：返回当前员工可使用的公共方法、提示词型 Agent 和已授权工作流，只有元数据，不返回密钥、完整提示词或工作流定义；部分来源失败会有警告。
- `GET /api/due-diligence/twins/:id/library-bindings`、`PUT` 同路径：仅所有者访问；写入要求 `expectedVersion`，创建递增的私有版本。
- `POST /api/due-diligence/twins/:id/library-learn`：仅创建待学习建议，重复来源按哈希去重。编辑和智能整理保留原始来源引用；确认时重新检查权限及版本。
- 清单生成接收 `librarySelection`，含 `skills` 和可选 `agent`。引用字段为 `source/id/version/hash`，来源包括 `prompt-skill`、`prompt-agent`、`capability-skill`、`workflow`。
- `GET /api/agent-blueprints/shared`、`PATCH /api/agent-blueprints/:id/sharing`：共享目录及带版本校验的所有者发布/撤回。

新增迁移 `0140_due_diligence_library_bindings`，只给 `digital_twins`、`digital_twin_versions` 增加 `library_bindings` JSON 列，默认空数组；不迁移或复制公司业务资料。模型配置、调用权限、项目权限、会话、审计、个人 Skill 版本继续复用原平台。公开分身不包含绑定、私有 Skill、原始素材或未确认建议。

调用前后都校验来源版本和当前员工权限；角色读取当前账号资料，不沿用客户端提交的权限信息。已更新或撤回的绑定不静默升级，而是停止参与并提示复核。明确选择但已失权的能力拒绝调用。工作流原有 Skill 的实际版本/哈希随快照记录。清单和对话保留实际使用的版本信息，历史消息不会重新带回已撤销的方法上下文。

## 模型、负载与取消

清单仍走 `ai-document`，分身构建及对话走 `interactive-assistant`；工作流复用其已授权的模型节点和原执行器，不新增供应商或密钥。工作流只进行受控文本处理，不下载依赖、不执行插件代码。没有后台 ASR 的环境不会因 Skill 整合而自动获得录音转写服务。

同一进程同时最多运行一个尽调工作流，复用原执行器的节点与总时限；输入有大小上限，预分析截取范围会提示。目录逐项读取并只保留摘要，避免同时保留全部指令。生成清单、构建和对话支持请求取消；取消不清空输入，已完成提交可能已经持久化，不能声称撤销了已保存结果。失败可重新发起；本轮没有增加跨进程的工作流断点续跑服务。

## 发布与独立运维说明

本轮在 `feature/due-diligence-library-integration-20261018` 开发，基于已保留同事正式环境未提交功能的兼容源码，不直接以 GitHub 主线覆盖生产。没有改动正式服务器、原本地业务库、服务端口或模型密钥。

发布前重新对齐实际生产源码和配置，确认当前迁移链已是正式兼容版本 `0139`，并检查 `0140` 编号没有被其他人占用。旧本地演示库的迁移编号与正式兼容分支不同，不能直接向旧库套用完整迁移链，也不能伪造迁移记录。本轮只在独立临时 MySQL 8 数据库验证新增迁移，临时库已移除。

部署时将 `0140` 随代码发布；使用现有 DDL 账号，先核对待执行迁移确实只有本次新增项，再按项目既有流程执行 `npm run db:migrate:separated`，随后运行 `npm run check:due-diligence-readiness`。这两条不是“让模型接入”的命令，不需要额外填一套模型 Key；公司原模型路由有效时直接复用。生产只接收本地构建产物，备份后低负载发布，不在生产构建或长录音压测。

回退保留新列和用户数据，不删除迁移历史。若要回退到不认识 `libraryRef` 的旧后端，必须先停用本轮来源为“平台能力学习”的衍生 Skill，或先给回退版本补齐来源访问守卫，避免旧代码忽略新来源权限。不能仅回退前端而留下不匹配的接口。

## 验证与未完成的联调

专项单元与接口测试覆盖：授权目录摘要、真实指令进入上下文、版本变化、撤回、类型伪造、按场景启停、去重、单工作流限流、取消后释放容量、调用现有工作流执行器、本人分身与公开分身隔离、所有者共享/撤回，以及原画布、会话草稿恢复。测试中的模型依赖均为合成替身，没有调用付费服务。

独立 MySQL 8 验证新增列默认值、中文旧数据和历史版本保留及 JSON 绑定写入。浏览器组件验收使用明确标注的合成接口，验证组合选择、启停、场景修改、保存提示及版本递增；它不是完整平台或真实员工的业务验收。前后端类型检查及本地生产构建通过；构建只生成候选，没有切换原本地服务或发布生产。

仍待真实模型与完整环境联调：公司具体工作流对真实项目材料的输出质量、真实角色授权目录与最终清单/分身的端到端效果。本地未配置授权模型，本轮不取用生产密钥、不把合成模型测试算作真实模型验收。
